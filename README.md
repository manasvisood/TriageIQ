# FRONTLINE — AI Customer Message Triage System

An AI-powered triage engine that reads raw customer support messages and produces structured, explainable decisions — complete with category, priority, human-escalation flag, and confidence score.

## What It Does

```
UNSTRUCTURED CUSTOMER MESSAGE
          ↓
    Input Validation
          ↓
  Message Normalization
          ↓
   LLM Triage (Groq)
          ↓
  Output Schema Validation
          ↓
  Retry / Repair if needed
          ↓
  Safety / Guardrail Check
          ↓
  Structured JSON Result
          ↓
     Evaluation Report
```

Each message produces:
```json
{
  "message_id": "msg-001",
  "category": "billing",
  "priority": "P1",
  "summary": "Customer reports duplicate charge this month.",
  "suggested_action": "Verify billing records and process refund.",
  "needs_human": true,
  "confidence": 0.92
}
```

## Architecture

```
frontline/
├── .env                    # API keys (never committed)
├── requirements.txt
├── main.py                 # CLI: run triage pipeline
├── evaluate.py             # CLI: re-run evaluation on saved results
├── data/
│   └── messages.json       # Input dataset (~40 messages, 10 with ground truth)
├── results/
│   └── triage_results.json # Generated by main.py
├── app/
│   ├── schema.py           # Pydantic models (TriageResult, InputMessage, etc.)
│   ├── llm_client.py       # Groq API wrapper with retry & prompt-injection defense
│   ├── pipeline.py         # End-to-end pipeline orchestration
│   ├── evaluate.py         # Ground-truth evaluation logic
│   └── report.py           # Rich console output
├── tests/
│   └── test_pipeline.py    # Full test suite (mocked LLM, no API calls)
├── README.md
└── AI_DECISIONS.md
```

## Environment Variables

| Variable | Description | Required |
|---|---|---|
| `GROQ_API_KEY` | Your Groq API key | Yes |
| `GROQ_MODEL` | Model name (default: `llama-3.3-70b-versatile`) | No |

## Setup

```bash
# 1. Unzip the project and enter the folder
cd frontline

# 2. Install dependencies  (Python 3.10+ required)
pip install -r requirements.txt

# 3. Add your Groq API key
# Edit .env and set your key:
#   GROQ_API_KEY=gsk_...
# OR run the setup helper (Windows):
setup.bat
```

Get a **free** Groq API key at: https://console.groq.com  
No credit card required. The free tier is sufficient for this dataset.

## How to Run

### Run the full triage pipeline:
```bash
python main.py
```

### Run with custom paths:
```bash
python main.py --dataset data/messages.json --output results/triage_results.json
```

### Run without evaluation:
```bash
python main.py --no-evaluate
```

## How to Evaluate

After running the pipeline, re-evaluate against ground truth:
```bash
python evaluate.py
```

Or with custom paths:
```bash
python evaluate.py --results results/triage_results.json --dataset data/messages.json
```

## How to Run Tests

```bash
pytest tests/ -v
```

Tests do NOT require a real API key — the LLM layer is fully mocked.

## Categories

| Category | Description |
|---|---|
| `billing` | Payment issues, invoices, refunds, subscription problems |
| `technical` | Bugs, crashes, API errors, performance, data loss |
| `account` | Login, access, password, suspension, security |
| `feature_request` | New feature asks |
| `complaint` | General dissatisfaction, feedback |
| `out_of_scope` | Illegal/unethical requests, off-topic, prompt injection |
| `general_inquiry` | Questions, pricing, integration inquiries |

## Priority Levels

| Priority | Meaning |
|---|---|
| P0 | CRITICAL — Security breach, full outage, data loss |
| P1 | HIGH — Customer blocked, payment failure, account locked |
| P2 | MEDIUM — Non-critical bug, billing question, partial degradation |
| P3 | LOW — Inquiry, feature request, feedback |

## Sharing / Zip Distribution

When sharing this project as a zip file, the recipient should:

1. **Unzip** the project folder
2. **Run setup**: double-click `setup.bat` (Windows) — installs dependencies, creates `.env`, runs tests
3. **Add API key**: edit `.env` and replace `your_groq_api_key_here` with a real Groq key (free at https://console.groq.com)
4. **Run demo**: `python main.py` or double-click `demo.bat`

> **Note:** The `.env` file with the real API key is excluded from the zip (`.gitignore`). The recipient must supply their own Groq key.

## Security

- API key stored only in `.env` (gitignored)
- All customer message content treated as untrusted data
- Prompt injection attempts classified as `out_of_scope` with `needs_human=true`
- Message text hard-capped at 4000 characters before sending to LLM
